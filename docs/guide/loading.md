# 页面加载与骨架屏

净读的常用列表页不再等整页数据查完才显示，而是**先把页面框架和骨架屏显示出来，再异步取回列表**。这样在弱网或站点繁忙时，用户能立刻看到页面结构，而不是一片空白。

## 作品广场：首屏直出 + 无限滚动

首页 `/` 是一个作品广场，不使用整页骨架：打开页面时第一页（12 件）的作品卡片已经在列表里，搜索引擎与关闭 JavaScript 的浏览器都能看到完整内容；启用 JavaScript 后，滚动到列表底部附近会自动请求 `/api/works`，把下一页的卡片追加到瀑布流。

- 页内类别标签只替换列表，不刷新整页；地址栏同步为 `/?type=project` 这类地址。
- 搜索、标签、作者筛选都通过同一个接口取数。
- 请求失败时显示重试按钮，不会清空已经加载的卡片。
- 旧入口 `/project`、`/forum`、`/blog`、`/resource/` 也展示同一作品流，同样首屏直出。

## 哪些页面会先显示骨架

- 小说库（`/book`）
- 月票榜（`/monthly-ticket`）

骨架的形状与真实卡片一致（封面、标题、标签、按钮），数据到达后直接替换，不会先撑开再塌回去。

## 分页与筛选也是异步的

在小说库与月票榜里，翻页与搜索只替换列表区域：

- 地址栏会同步更新，可以直接复制分享
- 浏览器「后退 / 前进」能恢复上一页列表
- 加载时列表区域显示骨架，顶部有细进度条
- 读屏器会播报「正在加载列表 / 列表已更新」

标签筛选是一个例外：书库的标签栏随页面一起直接给出，点标签会打开完整页面。这些标签落地页需要被搜索引擎收录，也适合直接分享；先给出标签栏还能避免列表加载完成后页面整体下移。作品广场的类别标签与卡片首屏也随页面直接给出，从第 2 页起才走 `/api/works`。

## 打不开或加载失败怎么办

1. 先检查网络，然后点列表里的「重新加载」。
2. 如果一直失败，点「直接打开完整列表」。它会以 `?ssr=1` 打开同一个页面，一次性拿到完整内容。
3. 关闭了 JavaScript 的浏览器会自动看到提示，也可以直接点这个完整列表链接。

## 对搜索引擎有影响吗

没有。无论列表是随后异步加载的，还是随页面直接给出的，搜索引擎拿到的都是完整内容：

- **普通浏览器**：小说库 / 月票榜先出骨架再填列表；作品广场首屏直出，滚动时再取下一页
- **搜索引擎爬虫**：拿到完整内容，保证收录
- **关闭 JavaScript 的浏览器**：同样拿到完整内容
- **`?ssr=1`**：始终返回完整内容

列表的异步更新部分不会被当作独立页面重复收录。
