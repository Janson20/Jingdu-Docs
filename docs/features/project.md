# 工程分享

「工程分享」用于发布**歌声合成工程、MIDI、UST / USTX 工程文件、翻调作品与教程**。
它与「资源分享」是两条独立的链路：资源分享只存**网盘链接**，工程分享把**文件本体**存在站内
（阿里云 OSS 香港节点），因此可以做到「点开即下载」，不需要跳转第三方网盘。

访问首页作品广场的 **工程** 标签（`/?type=project`），或旧的 `/project` 入口，可以浏览、搜索与发布；发布也可以在统一发布页 `/publish` 选择工程标签。

## 一、能分享什么

| 类型 | 说明 |
| --- | --- |
| 歌声合成工程 | VOCALOID / UTAU / Synthesizer V / CeVIO 等引擎的工程文件 |
| MIDI | 标准 MIDI 文件（`.mid` / `.midi`） |
| UST / USTX | UTAU 的工程与新一代工程格式 |
| 翻调 / 调校 | 基于他人作品的二次创作，须标明原曲来源 |
| 教程 | 文字、图片、PDF 形式的调校教程 |
| 其他 | 站内允许且通过格式校验的合规文件 |

**不接受**：DAW 工程（`.flp` `.ptx` `.logicx` `.cpr` 等）。这类文件体积大、依赖插件链、
脱离原环境基本无法打开，且极易夹带商业采样。

## 二、双通道：文件到底存在哪

本站有两条分发通道，**由文件格式自动决定**，发布者不需要也不应该手动选择：

| 通道 | 域名 | 承载内容 | 为什么 |
| --- | --- | --- | --- |
| A · CDN 加速 | `cdn.jingdu.org` | 合成工程、封面图、教程文档 | 内容版权风险低，可缓存加速 |
| B · OSS 直连 | `dl.jingdu.org` | MIDI、音频、PDF 文档 | 版权风险较高，不放进 CDN 缓存 |

**通道与工程类型都不由发布者选择**。上传文件后由服务端按其**扩展名**判定：

- 通道：`.vsqx` / `.ustx` / `.ust` / 图片 / 歌词与文档 → A（CDN）；`.mid` / `.midi` / 音频 / `.als` / `.musicxml` / `.pdf` → B（OSS 直连）
- 工程类型：`.vsqx`/`.ustx`/`.ust` → 歌声合成工程；`.mid` → MIDI；音频 → 翻调作品；歌词/文档/PDF → 教程；其余 → 其他

一个工程里混有多种文件时，通道按**最保守**的一票算：只要有一个文件落在 B，整个工程就记 B。工程类型取主文件的格式。

> **为什么不让发布者选**：真实的版权风险不由上传者的自我声明决定。早期版本允许勾选「自制原创」把内容升级到 CDN，实测下来等于让用户自己决定存储位置——而且 MIDI/音频一旦进了 CDN 缓存，下架时还得多花一次强制刷新。

填写标签时可以直接点下面的候选词（引擎 / 内容 / 用途三组），点一下追加、再点一下取消。词表只是引导，仍然可以自己写——工程圈的术语变得快，不适合做白名单。

> **管理员可以覆盖工程的默认通道**，但**不会移动已经上传的文件**——
> 对象在哪条通道由上传时的文件格式决定，改工程的默认通道只影响后续新文件。

## 三、上传方式

文件**不经过网站服务器**，由浏览器直接传到阿里云 OSS：

1. 浏览器向本站申请一个**预签名上传地址**（有效期很短）
2. 浏览器 `PUT` 到该地址，服务端不转发流量
3. 上传完成后通知服务端，服务端**回源校验**（大小、魔数、ZIP 结构）通过后才登记入库

- 单文件上限 **100 MB**（可在配置中调整）
- 超过 **50 MB** 自动改为**分片上传**，支持中断后续传
- 同一文件在同一工程内重复上传会被拒绝；跨工程上传相同文件会**复用已有对象**，不重复占用配额
- **存储文件名由服务端生成、纯数字**（形如 `1792218000123.mid`），你的原文件名只保存在数据库里，下载时通过 `Content-Disposition` 还原，所以你看到的仍是自己的文件名。这样签名串里不含任何用户输入，既避免了中文/特殊字符导致的偶发 403，也少了一个攻击面。扩展名会保留——CDN 的缓存规则按后缀匹配，丢了它命中率会崩

## 四、存储配额

| 项 | 数值 |
| --- | --- |
| 基础免费额度 | 500 MB |
| 每升 1 级增加 | 200 MB |
| 免费额度上限 | 2 GB（8 级） |
| 扩容包 | 5 GB / 30 天 / 1000 净币 |

删除工程会**释放配额**。配额统计按**实际占用的对象**计算，秒传复用同一文件不会被重复计费。

### 配额页入口

「工程存储配额」页面（`/project/quota`）集中显示已用空间、等级免费额度、扩容包额度、购买入口与配额变动记录。入口分布在日常操作路径上：

- 头像下拉菜单 →「工程存储配额」；
- 「我的作品」页头、「设置」页的「工程存储」；
- 工程库页头、「我解锁的工程」页头；
- 发布工程表单与工程编辑页的配额条（上传前就能看到余量并跳转购买扩容包）。

旧版「我的工程」页面已并入统一的「我的作品」，配额页的返回链接也指向「我的作品」。

## 五、解锁与下载计费

工程分**免费**与**付费**两种，由作者在发布/编辑时设定解锁价（净币，0 表示免费）。
升级前已发布的工程一律按免费处理，不追溯收费。

| 项 | 默认值 | 说明 |
| --- | --- | --- |
| 解锁价 | 50 净币 | 一次性；解锁后该工程**全部文件与后续版本**永久可下载 |
| 作者分成 | 80% | 解锁 50 时作者得 40，平台留 10 |
| 下载费 | 5 净币 / 次 | 全额归平台，抵消带宽并抬高批量抓取的成本 |
| 免费工程 | 两项都不收 | 教程类建议免费，否则传播不出去 |
| 作者本人 / 管理员 | 免费 | 自取自测不收费 |

**为什么解锁与下载分开收费**：解锁是对作品的付费，作者该拿钱；下载是每次的服务成本，
与「作品值多少钱」无关。混在一起会让「下一个文件」变成二次销售，用户会觉得被宰。

**退款**：工程被下架（举报成立或管理员处置）时，系统向全部解锁者**全额退还**解锁费，
写 `project_refund` 流水；已结算的作者收益不追回，退款由平台承担。下载费不退——
它是已发生的服务成本。

### 下载链路

```
POST /project/download/<asset_id>     校验解锁 → 扣下载费 → 签发票据 → 303
GET  /project/fetch/<nonce>           票据校验（归属/未过期/未用）→ 302 签名 URL
```

三个刻意的设计：

1. **下载必须是 POST**。GET 会被浏览器预取、被插件嗅探、被聊天软件生成链接预览，
   每一次都可能触发扣费。下载是有代价的动作，必须由用户显式点击。
2. **票据一次性且绑定账号**。`/fetch/<nonce>` 被转发给别人时，对方的 `user_uuid`
   对不上直接 403；本人用第二次则票据已置为已用。先 `peek` 校验归属再 `consume`，
   否则任何人拿到链接都能把票据「用掉」，让真正的买家下载失败。
3. **签名 URL 只活 60 秒**。CDN 与 OSS 两条通道都按 `deadline = now + 60` 反推签名时刻，
   实测 CDN 接受「签发时刻在过去、失效时刻在未来」的签名（`t = now-1740, ttl = 1800`）。

限频：单账号每分钟 6 次、每日 120 次（`PROJ_DOWNLOAD_PER_MINUTE` / `PROJ_DOWNLOAD_PER_DAY`）。
超限直接拦下并提示，不扣费。

## 六、审核与举报

- **文字信息先审后发**：工程名称、简介、标签在发布前经过自动审核；未通过会给出原因、可修改后重提；拿不准的转人工复核。
- **文件结构校验**：扩展名白名单、魔数校验、ZIP 容器结构限额（路径穿越、可执行文件、压缩比炸弹都会被拒）。
- **著作权声明**：发布时必须勾选，确认拥有著作权或已获授权。声明是后续下架与追责的依据。
- **举报**：详情页提供举报入口，可选「侵犯著作权 / 违法违规 / 恶意程序 / 标题不符 / 其他」。

下架时执行的是「**删源文件 + 强制刷新 CDN 缓存**」，不是仅仅从列表隐藏。阿里云的目录/正则刷新
默认是「标记刷新」，源站返回 304 时会继续命中旧缓存，因此必须用 API 的 `Force=true`。

## 七、在线试听

- **音频文件**（mp3 / flac / wav / m4a / ogg / aac）：详情页直接内嵌播放器，走签名 URL 的 Range 请求，可以拖进度条。
- **MIDI 文件**：点「试听」即可。服务端只解析出**音符事件**（起始时间、时长、音高、力度），前端负责发声。有两种音源可选：

| 音源 | 需要什么 | 说明 |
| --- | --- | --- |
| 网页合成（默认） | 无 | 浏览器内用 Web Audio 振荡器合成。任何浏览器、任何页面环境都能用，不弹权限框 |
| 系统 MIDI 音源 | Web MIDI 授权 + 系统有 MIDI 输出设备 | 把音符发给操作系统的 MIDI 合成器（Windows 上是 Microsoft GS Wavetable Synth 这类），音色接近真实乐器 |

> **Web MIDI 的两个前提**：页面必须在**安全上下文**（https 或 localhost）下打开，否则 `navigator.requestMIDIAccess` 根本不存在；首次使用会弹一次授权框。`http://局域网IP:端口` 这种地址下用不了，只能用网页合成。

> **为什么默认不是 MIDI**：`requestMIDIAccess()` 会弹权限框，而且非 https 环境下直接不可用。默认走网页合成可以保证「点了一定有反应」，需要更好音色时再手动切换。

MIDI 试听**不使用 SoundFont**。真实音色需要同时解决三件事：`spessasynth_lib` 与 `spessasynth_core` 两个 ESM 包（后者是裸导入，浏览器需要 importmap 或打包）、一个约 30 MB 的 GM 音源、以及相应的许可核实。试听的用途是「听旋律、节奏、和声对不对」，振荡器已经能达到目的，所以暂不引入。若将来升级，服务端的数据格式不用变，只需替换前端发声实现。

试听有两条限制：文件超过 2 MB 不下发（请下载后在本机打开）；MIDI 只放**前 30 秒**
（`PROJ_PREVIEW_SECONDS`，按时间截断而不是按音符数——后者会让慢歌听到一半、快歌听到全曲）。
音符数据本身就是作品，免费下发完整旋律等于把付费墙拆了。

## 八、常见问题

**为什么点下载会跳到别的域名？**

文件不在网站服务器上，下载地址是一个**60 秒有效的签名链接**。跳转前服务端会先校验解锁状态、
扣下载费、签发一次性票据，因此点了下载不等于「立刻开始下」，中间多一次同站跳转是正常的。

**为什么直接粘贴链接会 403 / 提示链接失效？**

签名链接绑定签名与时效，且只允许来自本站页面的请求；下载票据还与账号绑定、只能用一次。
把链接转发给别人，基本已经失效。

**上传时浏览器控制台报 CSP 拦截？**

`Content-Security-Policy` 的 `connect-src` 必须放行 OSS 直传端点，`media-src` 必须放行两条文件域名。这两项在 `app.py` 里从 `PROJ_OSS_*` 自动推导，改完要重启 Web 进程才生效。

**点下载没反应，控制台报 `form-action 'self'` 违规？**

说明当前页面是 **http** 打开的。浏览器因为 HSTS 会把相对的表单 `action` 升级成 https，
而 `form-action 'self'` 按文档 origin（http）匹配，两者不同源就被拦了。
现在有三道保险：

1. 走 http 的访客会被 301/308 跳到 https（只认反代给出的 `X-Forwarded-Proto: http`，没有该头不跳，避免循环）；
2. `form-action` 显式带上本站的 https 源（换域名时同步 `BASE_URL` 或设 `SITE_EXTRA_ORIGINS`）；
3. 下载**不再走表单提交**：前端用 `fetch` 拿到 `/project/fetch/<nonce>` 再跳转。
   因为 Chrome 对「表单提交的重定向链」同样套用 `form-action`，而下载最后一定跳到
   OSS/CDN，表单会在最后一跳被拦——这条是根治。

**上传报 403 `SignatureDoesNotMatch`？**

OSS 的签名把 **Content-Type** 算进去了，浏览器发送的值必须与服务端签进去的完全一致。本站由服务端按扩展名决定类型、通过 `/init` 的 `content_type` 回传，前端照发即可。用脚本直接 PUT 预签名地址时最容易踩这个坑——`requests` 默认不带该头，签名对得上；一旦自己加上或中间被代理补上，就会 403。

**上传中断了怎么办？**

分片上传的进度保存在浏览器本地，刷新页面后会从已完成的分片继续，不需要重传整个文件。

**为什么我的工程没有出现在首页？**

作品广场只展示已通过审核的工程。审核中或需要人工复核的，可以在「我的作品」里查看进度。
