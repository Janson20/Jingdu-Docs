# 歌姬档案

分两层：**引擎**（技术路线）与**声库**（具体某个声音）。内容都是人工维护的静态文件，
不是用户投稿区——声源、引擎型号写错比没有更糟。

## 一、数据在哪

| 文件 | 内容 | 是否入库 |
| --- | --- | --- |
| `content/engines.json` | 引擎条目（开发方、发布时间、授权、平台、优缺点、典型流程） | 是 |
| `content/vocaloids.json` | 声库条目（引擎系列、语言、声源、发布日期、调校要点）+ `featured` 首页推荐 | 是 |
| `data/vocaloid/hot.db` | 网易云热门代表作缓存 | 否（运行期数据，可随时重建） |

`data/` 目录整体被 gitignore，所以档案类内容必须放 `content/`，否则新环境部署出来是空页。

## 二、页面对应

- `/vocaloid/`：引擎卡片 + 按引擎系列分组的声库列表，可按系列筛选。
- `/vocaloid/<slug>`：单个声库，含调校要点与代表作。
- `/vocaloid/engine/<slug>`：单个引擎，含优缺点、流程，以及该系列下的声库。

声库页与引擎页互相跳转；首页只展示 `featured` 里的 6 条（不足时按引擎轮流补齐），
避免首页永远只出现同一系列。

## 三、代表作：抓什么、怎么更新

代表作取自网易云音乐的公开接口 `GET https://music.163.com/api/v1/artist/<id>`
（免登录，返回 `hotSongs`），每位取前 10 首，页面展示歌名、专辑与跳转链接。

**只存歌名、歌曲 ID 与链接，不下载、不转存任何音频。**

榜单是短期热门，所以**不写死在文件里**：

- 抓取结果写进 `data/vocaloid/hot.db`，页面只读缓存，请求链路里不联网；
- `scheduler.py` 在进程内跑一个守护线程，**每天定时刷新**（默认 04:30，本地时间）；
- 进程启动 20 秒后先补跑一次（覆盖「昨天关机」与「刚部署」两种情况）；
- 多进程部署时用 SQLite 里的 `job_lock` 互斥，只有一个进程真正执行；
  当天已成功跑过就跳过（`job_run` 表按日期去重），失败不算数、下次重试。

手动刷新：

```bash
python tools/fetch_hot_songs.py            # 全部
python tools/fetch_hot_songs.py --only kafu --show
```

## 四、洛天依为什么有两个来源

同一个名字在网易云有两个账号：官方的 `洛天依Official`，以及专门发布同人投稿的
`洛天依`。两个都要取——只取官方会漏掉社区创作，只取同人会看不到官方作品。
配置上写成数组，页面上每条歌带来源标签：

```json
"netease_artist_ids": [
  {"id": 906118,  "label": "官方"},
  {"id": 59655434, "label": "同人投稿"}
]
```

多个来源按「轮流取」合并，保证两边的歌都能上榜，而不是被数量多的一边盖掉。

## 五、艺人 ID 怎么定

`tools/resolve_netease_artists.py` 按候选名搜索并打印前几个候选（含专辑数与单曲数），
**不自动选取**：同名艺人太多（`洛天依Official` / `洛天依` / `プロジェクトセカイ`），
按名字或数量猜都会挂错人的作品。选完把 ID 写进 `content/vocaloids.json`。

## 六、注意事项

- 网易云接口没有公开配额，抓取脚本有 0.5~0.8 秒间隔，别调快。
- 服务器需要能访问 `music.163.com`；海外节点偶尔会慢或失败，脚本有重试，
  失败时保留旧榜单，不会把页面清空。
- 榜单只做「跳转入口」，不提供播放、不缓存音频，页面底部已注明版权归属。
