# 关注与私信

关注是站内的单向社交关系，作用有两个：主页展示关系、给私信加一道门槛。

## 一、关注

- 在任意用户主页点「关注」即可，无需对方同意；再点「已关注」取消。
- 主页展示 **关注数 / 粉丝数**，互相关注时显示「互相关注」标记。
- 关注列表与粉丝列表对所有人可见（`/user/<uuid>/following`、`/user/<uuid>/followers`）。

## 二、私信门槛

规则按「陌生人来敲门」的成本设计：

| 状态 | 能否发私信 |
| --- | --- |
| 未关注对方 | 不能，主页上的「发私信」会被拦下并提示先关注 |
| 已关注，对方未回复 | 最多发 **2 条**，输入框在额度用尽后收起 |
| 对方回复过任意一条 | 解除限制，可无限发送 |
| 互相关注 | 解除限制 |


### 几个刻意的取舍

- **对老会话向后兼容**：判定「对方是否回复过」不设时间下限，功能上线前就聊过的会话直接放行。
  否则老用户会在升级后突然发不出消息。
- **取消关注不回收会话**：限制针对「发起对话」，不是聊天本身。对方取关后消息突然发不出去，
  会把正常沟通一起掐断。
- **按会话计数，不按关注次数计数**：取消再关注不会重置那 2 条，避免「取关重关」无限刷。
- **拉黑优先级最高**：双向拉黑在门槛判定之前，被拉黑后无论关注与否都发不出去。
- **私信不送 AI**：私信只在本站做发送频率、重复内容与广告特征检测，不会把正文发送给第三方大模型；发送频率默认 10 条/分钟、200 条/天，重复内容会被拦截。

## 三、接口行为

`POST /message/api/send` 在门槛拦截时返回 **403** 而不是 400，并带上
`dm: {allowed, reason, remaining, following, mutual, unlocked}`，
页面据此显示「等对方回复」而不是笼统的「发送失败」。
